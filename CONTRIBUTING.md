# Contributing to island

Thanks for helping. island is a small Electron app with a hard constraint: it has to feel native and never get in the way of the rest of Windows. Please read [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) before changing window, input or rendering code.

## Setup

Requirements: Windows 11 or Windows 10 version 2004 or later (x64), [bun](https://bun.sh) 1.3 or later, and git. No .NET SDK or Visual Studio is needed: the C# helpers are compiled with the C# compiler that ships with Windows.

```powershell
git clone https://github.com/yatinannam/island
cd island
bun install
bun run start
```

The first run downloads the Electron binary (~100 MB) and compiles `media/bin/smtc.exe` and `activity/bin/islandctl.exe`. If the installed app is running, quit it first (`island.exe --quit`): both copies share the single-instance lock and `%APPDATA%\island`.

## Conventions

- **Use bun**, not npm or yarn, and commit `bun.lock` as generated by bun 1.3.x.
- **`media/smtc.cs` and `activity/islandctl.cs` are C# 5** (the in-box `csc.exe`): no string interpolation (`$""`), no `?.`, no `nameof`, no expression-bodied members. Async WinRT calls go through the polling `Await` helper.
- **Don't hide or move the island window** to "close" it; it breaks mouse input after the first click. Close it visually and leave it click-through (see [The island window](docs/ARCHITECTURE.md#the-island-window)).
- **Hit-testing lives in the main process tick** (`setMouse`), not in renderer hover events.
- **Keep the renderers sandboxed.** New capabilities go through a narrow `contextBridge` method and a validated `ipcMain` handler.
- **Editing on Windows:** don't round-trip source files through `Get-Content`/`Set-Content` in Windows PowerShell 5.1; it re-encodes UTF-8 as ANSI and adds a BOM. Use an editor.
- Comments explain *why* (constraints, Windows quirks), not what the next line does.

## Testing

There is no automated UI test suite yet; changes are verified on a real Windows desktop.

- `node --check` every JS file you touched.
- `ISLAND_DEBUG=1` logs open/close (with cursor coordinates), presses on the island, media state and shelf events to stdout.
- `ISLAND_SHOT=out.png bun run dev` saves a capture of the island page 1.8 s after opening. In glass mode the island is excluded from normal screenshots, so composite this capture over a screenshot of the region behind it to see the real result.
- `ISLAND_CSS="..."` injects CSS into the island page, e.g. to force a state for a screenshot.
- `paging.js` has no DOM and loads in Node: feed it wheel events (`{ t, dx, dy, notch }`, a zero-delta event when the fingers lift) and frames to check swipe changes without a touchpad.
- `CLAUDE_CONFIG_DIR=<empty folder>` makes island treat that folder as Claude Code's config, so the Claude Code switch can be tested without touching `~/.claude`.
- Scripted mouse tests (`SetCursorPos` + `mouse_event`) work, but place clicks on spots that are harmless on every page: a missed page switch otherwise lands on media controls and changes someone's playback.

### Flags, environment variables and hotkeys

| | |
|---|---|
| `--open` | Start with the island pinned open (`bun run dev`) |
| `--solid` | Use the solid background for this run |
| `--settings` | Open the settings flyout on start |
| `--quit` | Quit the running copy (exits at once if none is running) |
| `--start-with-windows on\|off` | Set the login item for this executable |
| `ISLAND_DEBUG=1` | Log open and close with cursor coordinates, presses on the island, media state, shelf and Claude Code events |
| `ISLAND_SHOT=<file.png>` | Save a capture of the island page 1.8 s after opening |
| `ISLAND_CSS=<css>` | Inject CSS into the island page |
| `CLAUDE_CONFIG_DIR=<folder>` | Claude Code's own setting for its config folder; island reads and writes its hooks there |
| <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>I</kbd> / <kbd>Q</kbd> / <kbd>J</kbd> | Pin the island open / quit / go to the Claude Code session that needs you (only while Claude Code is on) |

Launching a second copy without flags opens the settings flyout in the running one (single-instance lock).

### README images

`docs/images` is rendered from the real `island.html` with `scripts/readme-images.js` (offscreen, glass mode, a generated wallpaper as the screen behind the glass, 2x). Run one scene per process:

```powershell
$electron = '.\node_modules\electron\dist\electron.exe'
foreach ($s in 'hero', 'music', 'shelf', 'claude', 'peek-a', 'peek-b') { & $electron scripts\readme-images.js $s "$env:TEMP\$s.png" }
& $electron scripts\readme-images.js join "$env:TEMP\peek-a.png" "$env:TEMP\peek-b.png" docs\images\peeks.png
```

Then copy `hero`, `music`, `shelf` and `claude` (as `claude-code.png`) into `docs/images`.

Before opening a PR, check by hand: hover open/close, play/pause/next/seek (click and drag), page swipes (touchpad, both directions, and mouse wheel) and dots, the Claude Code switch on and off, drop in from Explorer, drag out (single, multi-select, drag all), double-click to open, settings flyout, and glass vs. solid. Say in the PR which of these you tested and which you could not.

## Pull requests

- Keep PRs focused; one feature or fix each.
- Describe the user-visible change and the Windows build/scaling you tested on.
- Update the README (user-facing behaviour) and docs/ARCHITECTURE.md (design, settings, IPC channels) when they change.

## Releasing (maintainers)

1. Bump `version` in `package.json`.
2. `bun run dist` → `dist/island-setup-<version>.exe`. It runs `scripts/build-helper.js` (compiles `smtc.exe` and `islandctl.exe` with the in-box `csc.exe`), `scripts/make-icon.js` (`build/icon.ico` and `build/icon.png` from `icon.js`, with a small built-in PNG/ICO encoder), and `electron-builder --win nsis` (no native modules; both helpers added through `extraResources`; a one-click, per-user NSIS installer).
3. `Get-FileHash dist\island-setup-<version>.exe -Algorithm SHA256`.
4. `gh release create v<version> dist/island-setup-<version>.exe --title "island <version>" --notes "<changes + SHA-256>"`.
