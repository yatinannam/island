# island

Windows 11 app that gives a Mac-style top "island": a glass notch-shaped island springs down from the top-center edge when the cursor rests there and shows what is playing, plus a file shelf. Owner: Yatin (yatinannam). Development happens on his Windows 11 machine (1920x1080 at 125%, single display), so the app can be run and screenshotted locally.

**Installed:** Yatin runs the installed build from `%LOCALAPPDATA%\Programs\island\island.exe` (NSIS per-user, Start menu shortcut, "Start with Windows" points there as `electron.app.island`). Quit it (`island.exe --quit`) before running the dev copy: both share the single-instance lock and `%APPDATA%\island`. To ship a change to him: `bun run dist`, then run `dist\island-setup-<version>.exe` (or `/S` for silent; it replaces the installed copy). Bump `version` in package.json for releases.

## Stack and decisions

- Electron with **bun** as package manager and script runner (`bun install`, `bun run start`, `bun run dev`). Do not use npm.
- Electron 45 downloads its binary on first run, not at install.
- Keep `bun.lock` generated by Yatin's bun (1.3.x). A lockfile from a newer bun fails to parse on his machine.
- **Removed:** the ripple overlay (Yatin did not like it) and the `--acrylic` mode (rectangular window, looked bad). Do not bring them back.
- **Look:** notch-shaped island attached to the top edge, with concave "ears" joining it to the edge, rounded bottom corners, soft shadow, like macOS notch apps. Yatin wants it **transparent like Windows' own transparency**, so the default is glass.
- **Glass:** CSS `backdrop-filter` in a transparent window blurs nothing, and DWM acrylic only fills a rectangle (with the `SetWindowRgn` route the edges are aliased). So the renderer captures the screen with `desktopCapturer` + `getUserMedia` (1/3 resolution, 15fps), the window has `setContentProtection(true)` so it is excluded from its own capture, and a canvas blurs the region behind the window and paints it inside the notch path: blur + `luminosity` layer + tint + noise (Windows acrylic recipe). Tested on Yatin's machine: no yellow capture border, no self-capture. Side effect: the island is invisible in screenshots and recordings; Solid in settings or `--solid` turns glass off. Settings "transparency" thins the luminosity and tint layers. Capture starts on open and stops 4s after close.
- Theme: follows `SystemUsesLightTheme` and `EnableTransparency` from the registry (re-read on each open and on `nativeTheme` updates). Transparency off means solid.
- The canvas paints the whole silhouette (shape, ears, shadow, edge) every frame while the CSS spring runs, reading `.island`'s size; `.shape` only clips content and catches the mouse.
- **Top edge and centering (fixed in 0.1.4):** `notchPath` starts its top edge at y=-2, above the window. On y=0 the arcs put the path on a softer anti-aliasing route and the first pixel row was ~75% opaque (alpha 191; a plain rect was 255): a 1px gap under the screen edge that Yatin saw. Electron also creates this frameless transparent window ~5 DIP too wide (481 for 476; installed it was 600 physical instead of 595), so the island sat 3 physical px right of center and off main's `shapeRect`; `createWindow` calls `setBounds(windowBounds(...))` once after construction. Measured after: top row solid from y=0, body 725-1195 physical, center 960.5.
- **One window:** 476x264 DIP (shape 380x140, or 380x216 with the shelf, plus padding for spring overshoot, ears and shadow), sized for the tallest island once since it is never resized, transparent, always-on-top, `focusable: false`, `backgroundThrottling: true` (must stay on, see below). Shown on first open, then **never hidden or moved** (only `setBounds` when the display changes). **Dead-clicks root cause (found 2026-11-08):** with `backgroundThrottling: false`, Electron never marks the page hidden, so when Windows hides the window (display off in Modern Standby, lock screen, fully covered, `hide()`, off-screen) Chromium hides its input child window `Chrome_RenderWidgetHostHWND` and never re-shows it (the re-show is on the page-shown path). Clicks then land on the top-level `Chrome_WidgetWin_1`, whose `WM_MOUSEACTIVATE` answer for a non-activatable window is `MA_NOACTIVATEANDEAT`: the button-down is eaten, only the up arrives, no `click`. This was both the old "hide/show kills clicks after the first use" bug and "clicks dead after sleep". Evidence: `hookWindowMessage` log showed `WM_MOUSEACTIVATE (1,513)` + `WM_LBUTTONUP` and page `pointerup` without `pointerdown`; the legacy child was `visible=False` (EnumChildWindows). Reproduced without sleep by covering the window with an opaque topmost window; in a replica, `backgroundThrottling: true` restored the child after cover and after `hide()`/`showInactive()`, and Yatin confirmed clicks work after a real sleep. Disabling `CalculateNativeWinOcclusion` also works but is global. Hiding the window may be usable again now (re-test clicks before relying on it). Downside: the transparent window stays over fullscreen apps.
- Mouse: the main tick calls `setIgnoreMouseEvents(false)` while the cursor is inside the shape rect, `true` otherwise (no `forward`). Electron's `{ forward: true }` forwarding never reached the page on Windows, so the old renderer `hover` IPC never fired and every click fell through.
- Controls: prev/next SVGs are exact mirrors, shifted so the icon's visual weight (not its bounding box) sits on the hover circle's center; measured within half a physical pixel. Play is balanced as drawn.
- Progress bar: 22px-tall `.scrub` grab area around the 4px bar (6px while hovered or dragged). Pointer capture drags and previews; seek is sent on release. During a drag the renderer sends `hold`, and main keeps the island open and taking the mouse even outside the shape. Stale positions for 1.5s after a seek are ignored. Tested with a real drag: stayed open outside the island, seeked to the release point.
- Equalizer bars: neutral white two-tone (`--eq-top`/`--eq-bottom`; near-black in light theme). Yatin did not like artwork-colored bars (purple etc.); artwork color stays in the background tint only.
- **Real equalizer** (`eq.js`, own file loaded after the main script; nothing else in island.html changed): the bars follow the system audio. `getUserMedia` with `chromeMediaSource: 'desktop'` for audio is WASAPI loopback of the default output; audio-only hangs, so it asks for a 16x16 1fps desktop video track too and stops it at once (the audio track stays live). No mic-in-use indicator (checked `CapabilityAccessManager\ConsentStore\microphone`). `AudioContext({ sinkId: { type: 'none' } })` so no output stream opens. Four bands (40-160, 160-600, 600-2400, 2400-10000 Hz), each scaled against its own 1s average and spread (a peak-relative scale left the bars near full on loud songs). Runs while `body` has `open` + `playing` (MutationObserver), stops 4s after. Falls back to the old CSS animation before the first sound, if capture fails, and after 1.5s of silence. `.eq.live i` needs `will-change: transform`, otherwise every frame repaints the content. Tested with a synthetic stream and with Yatin's Spotify in an offscreen harness and the real dev app (glass on). Cost: about +0.06 core over the CSS animation while open and playing (harness 0.275 vs 0.21); dev app open + glass + playing 0.41 core.
- **Live activities (Claude Code), 0.2.0.** Rules were decided with Yatin in a quiz; keep them: working = no peek (listed on a third page "Activity"); finished = 5s peek only if the turn ran >= 20s and its terminal is not the foreground window; needs you (Notification `permission_prompt`, `idle_prompt`, `elicitation_dialog`) = always peeks, stays until that session continues (PostToolUse/PostToolUseFailure/PermissionDenied/UserPromptSubmit/Stop) or the pill is clicked/dismissed; subagent finished = counter only; queue one at a time, needs first, a needs pill yields after 5s; held (no chime) during fullscreen/presentation (`SHQueryUserNotificationState`), Do Not Disturb and lock/sleep, dropped after 30 min; island open = one-line banner; custom Web Audio chimes (rising finished, double tap needs, falling error); peek text = project folder + status + tool only (no message text); same-folder sessions numbered ("island 2"); session "closed" when its Claude pid exits, "idle" after 2 min without events (Esc sends no hook); Ctrl+Alt+J = latest needs-you else latest finished; clicking pill/row focuses the terminal window (not the tab). Pieces: `activity/islandctl.cs` (C# 5, `/target:winexe` so no console flash; `hook` keeps a few top-level string fields with a small scanner, finds the Claude pid = first non-shell ancestor and the terminal via `AttachConsole` + `GetConsoleWindow` + `GetAncestor(GA_ROOTOWNER)` (Windows Terminal's pseudo-console window is owned by the WT window; verified: gives WT's `CASCADIA_HOSTING_WINDOW_CLASS` window for Yatin's claude.exe, which runs under cmd.exe from Explorer, so the window is not an ancestor process), sends one line to `\\.\pipe\island-<user>`, prints nothing, exits 0, ~85ms; `state` = `{quns, dnd, fg, fgRoot}`; `focus <hwnd>` = `AttachThreadInput` + `SetForegroundWindow`, verified switching Chrome -> WT), `activity/hub.js` (pipe server + rules), `activity/claude-hooks.js` (connect/disconnect in `~/.claude/settings.json`: exec form `command` = islandctl path + `args: ["hook"]`, `async: true`; backup `settings.island-backup.json`; ours = command ending `islandctl.exe` with args[0] `hook`; byte-identical round trip tested), `activity-view.js` (pill, page, banner, chimes). **DND:** `SHQueryUserNotificationState` stays 5 with Windows 11 Do Not Disturb on; the WNF state `WNF_SHEL_QUIETHOURS_ACTIVE_PROFILE_CHANGED` (0x0D83063EA3BF1C75 via `NtQueryWnfStateData`) is 1 when on, 0 off (Yatin toggled it while sampled). The canvas frame loop must treat `body.peek` as visible (it starts at height 0 and the loop stopped: no pill drawn). **Claude can't connect the hooks for Yatin:** the auto-mode classifier denies Claude writing hooks into `~/.claude/settings.json` (self-modification); Yatin flips *Connect Claude Code* himself.
- Hover: main process polls `screen.getCursorScreenPoint()` every 16ms, uses the display under the cursor. Hot zone 240x3 DIP at top center. Open delay (dwell) and close delay come from settings, defaults 150ms and 120ms (Yatin asked for a faster close; was 300ms).
- Animation: damped spring sampled into a CSS `linear()` easing at startup (open: stiffness 240, damping 21, ~180ms to 95%; close: 560/48, ~210ms to 95%). Width/height animate; content fades and unblurs after the shape grows.
- Song color: the artwork's dominant vivid hue is washed over the material (uniform layer + radial glow from the artwork), alpha = songColor setting, lerped between tracks. Applies to glass and solid.
- Settings: `settings.js` stores `%APPDATA%\island\settings.json` (glass, transparency, songColor, openDelay, closeDelay). Tray left-click opens `settings.html`, a 360px frameless window with `backgroundMaterial: 'acrylic'`, Windows accent from `systemPreferences.getAccentColor()`. It copies Windows' own tray flyouts as recorded frame by frame on Yatin's build (26H2, animation effects on): placed in the work-area corner on the tray's side, 12px from the edge and the taskbar; no slide; the panel appears in place and the content fades in (167ms); on close the page fades its content out (80ms), main hides at 120ms and DWM fades the empty panel (Windows shows a window's last frame on the next show, so this keeps the next open from flashing old content). Windows' acrylic for this window is lighter and more see-through than its own flyouts (Yatin: "too bright"), so the page paints a tint on `html` (`--tint`, dark `rgba(26,26,26,0.6)`); it is on `html`, not the fading `.panel`, so the panel is dark from its first frame. Layout is the Windows Settings card pattern (title + description left, control right, On/Off next to switches), a darker footer band (Pin open, Quit), and a Shelf card (file count, Clear). Sizing: `useContentSize` + `setContentBounds`, and the page reports its natural height (`.scroll` scrollHeight + footer), never `document.scrollHeight`; the old `setSize` on the outer frame + `scrollHeight` grew the flyout ~2px per open at 125%. Changing a look setting holds the island open on the primary display (`previewing`) until the flyout hides. Start with Windows uses `app.setLoginItemSettings` (electron.exe + project dir in dev). Blur hides the flyout, except in the first 400ms after showing.
- Hotkeys: Ctrl+Alt+I pins open/closes, Ctrl+Alt+Q quits, Ctrl+Alt+J goes to the Claude session that needs you. Tray right-click menu: Settings, Pin, Quit. Single-instance lock; a second launch with `--quit` closes the running copy cleanly (`bun run quit`), without it opens settings. `--settings` opens the flyout on start (for screenshots).
- Tray icon: `icon.js` draws a screen outline with the island notch (SDF, 4x4 supersampled) at 16/20/24/32 px, white on a dark taskbar, near-black on light. Tooltip shows the current track.
- Tray visibility: Yatin wants the icon always on the taskbar. Windows keeps new icons in the `^` overflow and stores the choice in `HKCU\Control Panel\NotifyIconSettings\<id>` `IsPromoted` (DWORD). The Tray GUID is derived from `process.execPath` (`guidForPath` in main.js): unsigned, Windows ties a GUID to one exe path, so dev, `dist\win-unpacked` and the installed app each need their own; the same path always gets the same GUID. `tray-visibility.js` finds the entry by `IconGuid` (query `/s /v IconGuid`; never `/s /f`: every entry holds a PNG snapshot and the search takes over a minute), writes IsPromoted, re-checks after 1.5s and rewrites (Explorer may write its default right after creating the entry). Explorer applies it live. Done once per GUID (`trayPromotedGuids` in settings), then the "Always show icon on taskbar" toggle controls it. Verified on Yatin's machine: stays promoted across clean quit, force-kill and restart.
- `ISLAND_DEBUG=1` logs open/close with cursor coordinates. Do not use `--debug` as a flag: Node intercepts it.
- **Media:** `media/smtc.cs` (C# 5 only: no `$""`, no `?.`) is compiled at runtime by `media/helper.js` with `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe` against `System.Runtime.dll`, `System.Runtime.InteropServices.WindowsRuntime.dll` and the `System32\WinMetadata` winmd files into `media/bin/smtc.exe` (gitignored). No .NET SDK on Yatin's machine, and `AsTask` is unavailable without the SDK's union metadata, so async calls are awaited by polling `Status`. It follows Windows' current SMTC session, emits JSON lines (state, art as base64, errors) and reads `toggle|next|prev|seek <ms>` on stdin; it exits when stdin closes. Renderer extrapolates position from `updatedAt` while playing and takes the accent color from the artwork.
- `@coooookies/windows-smtc-monitor` was tried and dropped: read-only, no play/pause/skip/seek.
- **File shelf** (`shelf.js`): references to files (no copies), persisted in `%APPDATA%\island\shelf.json`; drops with no path (browser images) are written to `%APPDATA%\island\shelf-files\<id>\` and only those are ever deleted by us. Drop in: renderer drag events (the window takes the mouse while the cursor is over the shape, so OLE drops reach it), paths via `webUtils.getPathForFile` in preload. Multi-select (renderer only): long press a tile (400ms without moving) or Ctrl+click enters select mode; clicks tick/untick; dragging a ticked tile drags all ticked (main's `shelf-drag` already takes many ids); Done, a drag-out or closing the island ends it. Moving before 400ms is a normal single drag. `#dragAll` needs `-webkit-user-drag: element` because the global `button { all: unset }` clears it (that was the "drag all gives a path" bug). Double-click opens via `shell.openPath` (logged). **Testing warning:** a scripted wheel to the Shelf page once failed on the first open and the clicks landed on the music page, seeking his paused video; place test clicks on spots that are empty on the music page too.
**Pages (Yatin picked this over the grow-down row):** the island never changes size; Music and Shelf are two 380x140 pages in a `.pages` track (`--page` 0/1, spring `--ease-page`). Scroll on the island rolls one page per gesture (sideways scroll over a long shelf scrolls the files), dots at the top center switch too. Touchpad momentum keeps sending wheel events for ~1s after a swipe: the 450ms cooldown only blocks the direction of the last page change, and scrolling past the last page neither accumulates nor re-arms it (it used to, so a swipe back waited up to ~1s; reproduced and checked with simulated momentum in an offscreen window, about 30ms after the fix), and the shelf dot shows the file count from the music page. Every open starts on Music; dragging a file over the island switches to Shelf. Renderer still reports `shape-size` (always 140); main's `SHELF_H`/taller window are now unused headroom. Drag out: renderer `dragstart` -> `preventDefault` -> IPC -> `webContents.startDrag({ files, icon })` in main; moved files are pruned. Thumbnails: `nativeImage.createThumbnailFromPath` (shell previews), fallback `app.getFileIcon`. Tested on Yatin's machine with a real OLE drag from a WinForms test window (scratch `dragform.ps1`): drop in added the file, drag out delivered it to the window, original kept (copy).
- **Packaging:** `bun run dist` = `scripts/build-helper.js` (compiles smtc.exe) + `scripts/make-icon.js` (build/icon.ico from `icon.js` `renderApp`, own PNG/ICO encoder) + electron-builder 26 NSIS (one-click, per-user). smtc.exe ships as `resources/smtc.exe` (`extraResources`); main passes it to MediaHelper when `app.isPackaged`. `npmRebuild: false` (no native deps). Unsigned: SmartScreen warns on other machines. `--start-with-windows on|off` sets the login item for the running exe (used to move Yatin's login item from the dev copy to the installed one).
- **Editing files from PowerShell:** never round-trip source files through `Get-Content`/`Set-Content` in Windows PowerShell 5.1: it reads UTF-8 as ANSI and writes a BOM (it once turned `·` into `Â·` in main.js). Use the Edit/Write tools. For commit messages with quotes, use `git commit -F <file>`.

## Testing notes

- Input diagnostics without touching project code: `electron.exe -r <diag.js> .` (Electron's own preload flag; `NODE_OPTIONS=--require` loads before `electron` resolves). The module can `hookWindowMessage` on the island window, wrap `setIgnoreMouseEvents`, log `powerMonitor`/`screen` events and inject page listeners via `executeJavaScript` + `console-message`. Check the input child from outside with a DPI-aware `EnumChildWindows` (`Chrome_RenderWidgetHostHWND` visible?). A non-DPI-aware PowerShell gets 96-DPI (virtualized) window rects.

- Driving the settings flyout without touching Yatin's keyboard or mouse: start the dev copy with `--remote-debugging-port=9333`, then evaluate JS in a page over CDP (`http://127.0.0.1:9333/json`, `Runtime.evaluate`; bun has `fetch` and `WebSocket`), e.g. `window.settings.action('hide')`. A relaunch (`electron .`) shows the flyout through `second-instance`. The dev copy shares `settings.json` with the installed app, so a value changed in the dev flyout changes his real settings.
- Layout previews without any window on screen: a scratch Electron app with `webPreferences: { offscreen: true }` loading `settings.html` with a mock `window.settings`, `capturePage()`, composited over grey. Set `nativeTheme.themeSource` for light/dark; one page load per process (a second `loadFile` in the same process failed with ERR_FAILED).

- `ISLAND_CSS="<css>"` injects CSS into the island page (e.g. force button backgrounds to measure centering from an `ISLAND_SHOT` capture).
- `bun run dev` starts pinned open. With glass on, GDI screenshots do not show the island (content protection). Set `ISLAND_SHOT=<file.png>` to save `webContents.capturePage()` 1.8s after opening, and composite it over a DPI-aware `CopyFromScreen` of the top-center strip to see the real look.
- Avoid driving Yatin's mouse while he is using the machine: his real cursor moves interfere. When a click test is needed (he asked us to check a click bug), a scratch script moves to the hot zone, then onto play (physical 960,144 at 125%), clicks with `mouse_event`, and restores the cursor; `ISLAND_DEBUG=1` logs `renderer: pointerdown ...`, `media-cmd` and media state. Toggle an even number of times so his music ends as it was.
- Measured: closed idle 1.6% of one core (electron + smtc.exe); open with glass about 0.3 core, open solid about 0.18 core (the equalizer animation); about 350MB RAM, smtc.exe 33MB. With the real equalizer, open + glass + playing about 0.41 core.
- Live activities without touching his Claude settings: write hook JSON files and pipe them to `activity/bin/islandctl.exe hook` (the dev island listens on the pipe; the 0.1.x installed app does not, so a scratch harness can own the pipe while it runs). Write the JSON with the Write tool: the Bash tool drops doubled backslashes. Drive the dev island over CDP (`window.settings.action('pin')` opens it, `document.getElementById('pillLabel').click()` clicks the pill). The rules have a scripted test with a fake `ctl` (scratch `hubtest.js`). Real mouse clicks on the pill and hover-pause were not tested by script.
- Equalizer without music on his speakers: a scratch Electron app can load the real `island.html` + `preload.js` (answer `snapshot`, send `island-state`/`media-state`) and replace `navigator.mediaDevices.getUserMedia` with a synthetic `MediaStreamAudioDestinationNode` stream. Keep that test window visible (topmost, opacity 0.01, click-through): when it is covered, Windows' occlusion pauses rendering and the page never gets `open`.
