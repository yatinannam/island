# island

Windows 11 app that gives a Mac-style top "island": a glass notch-shaped island springs down from the top-center edge when the cursor rests there and shows what is playing (more modules later). Owner: Yatin (yatinannam). Development now happens on his Windows 11 machine (1920x1080 at 125%, single display), so the app can be run and screenshotted locally.

## Stack and decisions

- Electron with **bun** as package manager and script runner (`bun install`, `bun run start`, `bun run dev`). Do not use npm.
- Electron 45 downloads its binary on first run, not at install.
- Keep `bun.lock` generated by Yatin's bun (1.3.x). A lockfile from a newer bun fails to parse on his machine.
- **Removed:** the ripple overlay (Yatin did not like it) and the `--acrylic` mode (rectangular window, looked bad). Do not bring them back.
- **Look:** notch-shaped island attached to the top edge, with concave "ears" joining it to the edge, rounded bottom corners, soft shadow, like macOS notch apps. Yatin wants it **transparent like Windows' own transparency**, so the default is glass.
- **Glass:** CSS `backdrop-filter` in a transparent window blurs nothing, and DWM acrylic only fills a rectangle (with the `SetWindowRgn` route the edges are aliased). So the renderer captures the screen with `desktopCapturer` + `getUserMedia` (1/3 resolution, 15fps), the window has `setContentProtection(true)` so it is excluded from its own capture, and a canvas blurs the region behind the window and paints it inside the notch path: blur + `luminosity` layer + tint + noise (Windows acrylic recipe). Tested on Yatin's machine: no yellow capture border, no self-capture. Side effect: the island is invisible in screenshots and recordings; Solid in settings or `--solid` turns glass off. Settings "transparency" thins the luminosity and tint layers. Capture starts on open and stops 4s after close.
- Theme: follows `SystemUsesLightTheme` and `EnableTransparency` from the registry (re-read on each open and on `nativeTheme` updates). Transparency off means solid.
- The canvas paints the whole silhouette (shape, ears, shadow, edge) every frame while the CSS spring runs, reading `.island`'s size; `.shape` only clips content and catches the mouse.
- **One window:** 476x188 DIP (shape 380x140 plus padding for spring overshoot, ears and shadow), transparent, always-on-top, `focusable: false`, `backgroundThrottling: false`. Shown on first open, then **never hidden or moved** (only `setBounds` when the display changes): after a click, a `hide()`/`showInactive()` cycle or moving it off-screen made Electron stop delivering mouse presses to it (moves still arrived), so the controls went dead after the first use. Verified on Yatin's machine: hide/park = only the first click works; stay in place = 4/4. Root cause unknown; multi-monitor moves may still hit it. Downside: the transparent window stays over fullscreen apps.
- Mouse: the main tick calls `setIgnoreMouseEvents(false)` while the cursor is inside the shape rect, `true` otherwise (no `forward`). Electron's `{ forward: true }` forwarding never reached the page on Windows, so the old renderer `hover` IPC never fired and every click fell through.
- Controls: prev/next SVGs are exact mirrors, shifted so the icon's visual weight (not its bounding box) sits on the hover circle's center; measured within half a physical pixel. Play is balanced as drawn.
- Progress bar: 22px-tall `.scrub` grab area around the 4px bar (6px while hovered or dragged). Pointer capture drags and previews; seek is sent on release. During a drag the renderer sends `hold`, and main keeps the island open and taking the mouse even outside the shape. Stale positions for 1.5s after a seek are ignored. Tested with a real drag: stayed open outside the island, seeked to the release point.
- Equalizer bars: neutral white two-tone (`--eq-top`/`--eq-bottom`; near-black in light theme). Yatin did not like artwork-colored bars (purple etc.); artwork color stays in the background tint only.
- Hover: main process polls `screen.getCursorScreenPoint()` every 16ms, uses the display under the cursor. Hot zone 240x3 DIP at top center. Open delay (dwell) and close delay come from settings, defaults 150ms and 120ms (Yatin asked for a faster close; was 300ms).
- Animation: damped spring sampled into a CSS `linear()` easing at startup (open: stiffness 240, damping 21, ~180ms to 95%; close: 560/48, ~210ms to 95%). Width/height animate; content fades and unblurs after the shape grows.
- Song color: the artwork's dominant vivid hue is washed over the material (uniform layer + radial glow from the artwork), alpha = songColor setting, lerped between tracks. Applies to glass and solid.
- Settings: `settings.js` stores `%APPDATA%\island\settings.json` (glass, transparency, songColor, openDelay, closeDelay). Tray left-click opens `settings.html`, a 340px frameless window with `backgroundMaterial: 'acrylic'` above the tray, Windows accent from `systemPreferences.getAccentColor()`. Changing a look setting holds the island open on the primary display (`previewing`) until the flyout hides. Start with Windows uses `app.setLoginItemSettings` (electron.exe + project dir in dev). Blur hides the flyout, except in the first 400ms after showing.
- Hotkeys: Ctrl+Alt+I pins open/closes, Ctrl+Alt+Q quits. Tray right-click menu: Settings, Pin, Quit. Single-instance lock; a second launch with `--quit` closes the running copy cleanly (`bun run quit`), without it opens settings. `--settings` opens the flyout on start (for screenshots).
- Tray icon: `icon.js` draws a screen outline with the island notch (SDF, 4x4 supersampled) at 16/20/24/32 px, white on a dark taskbar, near-black on light. Tooltip shows the current track.
- Tray visibility: Yatin wants the icon always on the taskbar. Windows keeps new icons in the `^` overflow and stores the choice in `HKCU\Control Panel\NotifyIconSettings\<id>` `IsPromoted` (DWORD). The Tray has a fixed GUID (`TRAY_GUID` in main.js; tied to the electron.exe path while unsigned) so the entry is stable. `tray-visibility.js` finds the entry by `IconGuid` (query `/s /v IconGuid`; never `/s /f`: every entry holds a PNG snapshot and the search takes over a minute), writes IsPromoted, re-checks after 1.5s and rewrites (Explorer may write its default right after creating the entry). Explorer applies it live. Done once on first run (`trayPromoted` in settings), then the "Always show icon on taskbar" toggle controls it. Verified on Yatin's machine: stays promoted across clean quit, force-kill and restart.
- `ISLAND_DEBUG=1` logs open/close with cursor coordinates. Do not use `--debug` as a flag: Node intercepts it.
- **Media:** `media/smtc.cs` (C# 5 only: no `$""`, no `?.`) is compiled at runtime by `media/helper.js` with `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe` against `System.Runtime.dll`, `System.Runtime.InteropServices.WindowsRuntime.dll` and the `System32\WinMetadata` winmd files into `media/bin/smtc.exe` (gitignored). No .NET SDK on Yatin's machine, and `AsTask` is unavailable without the SDK's union metadata, so async calls are awaited by polling `Status`. It follows Windows' current SMTC session, emits JSON lines (state, art as base64, errors) and reads `toggle|next|prev|seek <ms>` on stdin; it exits when stdin closes. Renderer extrapolates position from `updatedAt` while playing and takes the accent color from the artwork.
- `@coooookies/windows-smtc-monitor` was tried and dropped: read-only, no play/pause/skip/seek.
- References in Yatin's message: Pillar (Tauri, MIT, code usable with credit) and notchX (Flutter + C++, all rights reserved, ideas only).

## Testing notes

- `ISLAND_CSS="<css>"` injects CSS into the island page (e.g. force button backgrounds to measure centering from an `ISLAND_SHOT` capture).
- `bun run dev` starts pinned open. With glass on, GDI screenshots do not show the island (content protection). Set `ISLAND_SHOT=<file.png>` to save `webContents.capturePage()` 1.8s after opening, and composite it over a DPI-aware `CopyFromScreen` of the top-center strip to see the real look.
- Avoid driving Yatin's mouse while he is using the machine: his real cursor moves interfere. When a click test is needed (he asked us to check a click bug), a scratch script moves to the hot zone, then onto play (physical 960,144 at 125%), clicks with `mouse_event`, and restores the cursor; `ISLAND_DEBUG=1` logs `renderer: pointerdown ...`, `media-cmd` and media state. Toggle an even number of times so his music ends as it was.
- Measured: closed idle 1.6% of one core (electron + smtc.exe); open with glass about 0.3 core, open solid about 0.18 core (the equalizer animation); about 350MB RAM, smtc.exe 33MB.

## Roadmap

1. Compact "live activity" peek: on track change, show a small pill for ~3s without hover.
2. Media polish: scrolling long titles, app icon, volume.
3. Extras in order: timer, clipboard history, file shelf, voice mode (mic waveform and live transcript).
4. Ship: start with Windows, settings page, hide when a fullscreen app is active, multi-monitor polish.

## Known limits

- Overlays do not show over exclusive-fullscreen games.
- Reading other apps' notifications (UserNotificationListener) likely needs a packaged app (MSIX) with the listener capability. Unverified.
